# 検証状況

2026-10-20、Windows x64 / Node.js 24.16.0 / Rust 1.98.1 で実施しました。CI・配布先・実機での確認とは区別しています。

## ローカルで確認したこと

- TypeScript の型検証、Vite の本番ビルド、Prettier、Rustfmt、Clippy。
- Rust 内のURL検証テスト2件。秘密情報を含むURL、パス付きURL、外部HTTP、曖昧なURLを拒否します。
- Chromium で7種類の表示サイズ。1440×960、1280×840、1024×768、884×1000、390×844、320×740、844×390で横方向のはみ出しがないことを確認しました。
- 入力エラー、消去、テーマ保存、ダイアログ、キーボード操作など、ブラウザー上の操作9項目。
- 同梱画面を持つ Windows デバッグビルドの起動と、実際の WebView2 上の12項目。既存の Yumunio サーバーと Better Auth を一時的なメモリーDBで起動しました。
- Windows NSIS インストーラーの生成。署名は行っていません。インストール操作や配布は行っていません。
- pen.dev デスクトップ版で8画面・5種類の共通部品・基礎フレームを作成し、画像で確認しました。同日、利用者による保存後、ディスク上の原本更新を確認しました。

## WebView2 で確認した12項目

1. 同梱画面の初回表示とネイティブIPCの接続。
2. 接続確認前のサーバー遷移を拒否。
3. HTTP転送を応答として返すサーバーを拒否。
4. 64 KiBを超える応答を拒否。
5. Yumunio の契約と異なる応答を拒否。
6. 接続確認で転送先へリクエストを送らない。
7. 既存の Node 版 Yumunio の公開APIと公開名を取得。
8. サーバー画面からメールとパスワードでログインし、HttpOnly Cookieを保持。
9. ページ再読込後もログイン状態を保持。
10. 接続先ページからアプリ専用コマンドを呼べない。
11. ナビゲーションボタンで選択画面に戻り、接続先情報を再表示。
12. 保存済みサーバーを端末内のリストから削除。

検証用スクリプト、スクリーンショット、ログ、WebViewプロファイル、Rust のビルド結果は公開ソースの外に置いています。利用者のデータは変更していません。

## Yumunio 本体の自動保存

アプリが表示するサーバー側の編集画面にも変更を加えました。この実装は Yumunio 本体のリポジトリで管理します。

- タイトル・本文・プロパティ・ページの見た目を自動で反映し、通常の保存ボタンや保存状態の表示をなくしました。
- 既存テスト1,923件が成功しました。検証用のプロパティ競合・追加入力の保持テスト6件も、リポジトリ外で成功しました。
- Chromium の操作確認11項目で、日本語変換中の待機、遅い返答の間の追加入力、ページ移動、詳細パネル終了、表示設定、通信失敗時の入力保持を確認しました。
- デスクトップ・タブレット・スマートフォンの表示を確認しました。各端末のネイティブWebViewでの確認とは区別しています。
- pen.dev の編集画面18件を更新し、通常時と通信失敗時の見た目を画像で確認しました。利用者による原本保存後、ディスク上の更新を確認しました。
